A Modern board is styled through a public contract: CSS variables, class hooks and data attributes. Everything on this page is public API. Anything not listed here is internal and can change in any release.

The contract applies to Modern boards only. Classic boards keep their `flowforge-*` classes and are not affected by anything below.

## Layering

Flowforge ships plain CSS. It contains no Tailwind utilities and no `@apply`, so your app needs no `@source` line and a Tailwind `prefix()` cannot break it.

The stylesheet opens with the layer order Filament uses, and puts every rule in one sublayer:

```css
@layer properties, theme, base, components, utilities;

@layer components.flowforge {
    /* every rule */
}
```

Your unlayered CSS always beats flowforge's. Your layered CSS wins when it sits in `components` itself or in a later layer such as `utilities`.

Filament's own component styles sit in `components`, which outranks the `components.flowforge` sublayer. Flowforge uses `!important` in the few places it must beat them. See [Properties set with !important](#properties-set-with-important).

Filament panels get the stylesheet in the page head. A standalone board links it in its own markup. You do not register or import it.

## Variables

Flowforge never sets a public `--ff-*` variable. Each rule reads the variable through a private alias with a default, so a value you set at any scope wins. That scope can be `:root`, `.ff-board` or one card.

The dark column shows where the default changes under Filament's `.dark` class. A single value applies to both modes.

| Variable | Tier | Default (light / dark) | Since | Used for |
|---|---|---|---|---|
| `--ff-surface` | semantic | `var(--gray-50)` / `var(--gray-950)` | 4.2.0 | Paints the sticky lane-header strip. Set it to the page background. |
| `--ff-surface-sunken` | semantic | `var(--gray-100)` / `color-mix(in oklab, #fff 5%, transparent)` | 4.2.0 | Column tray background. `--ff-tray-bg` overrides it. |
| `--ff-surface-raised` | semantic | `#fff` / `var(--gray-900)` | 4.2.0 | Card and filters panel background. `--ff-card-bg` overrides it for cards. |
| `--ff-border` | semantic | `color-mix(in oklab, var(--gray-950) 5%, transparent)` / `color-mix(in oklab, #fff 10%, transparent)` | 4.2.0 | Card ring and filters panel ring. `--ff-card-ring` overrides it for cards. |
| `--ff-text` | semantic | `var(--gray-950)` / `#fff` | 4.2.0 | Column and lane titles and the add row on hover. |
| `--ff-text-muted` | semantic | `var(--gray-500)` / `var(--gray-400)` | 4.2.0 | Counts, summaries and card meta. |
| `--ff-accent` | semantic | `var(--primary-500)` | 4.2.0 | Outline of an accepting drop target, the drop gap border and the loading text. |
| `--ff-accent-tint` | semantic | `var(--primary-50)` / `color-mix(in oklab, var(--primary-500) 10%, transparent)` | 4.2.0 | Tint behind an accepting drop target. |
| `--ff-danger` | semantic | `var(--danger-500)` | 4.2.0 | Outline of a refusing drop target and the limit hint. |
| `--ff-warning` | semantic | `var(--warning-600)` / `var(--warning-400)` | 4.2.0 | Count of a full column. |
| `--ff-radius` | semantic | `0.75rem` | 4.2.0 | Card radius. The tray radius is this plus `0.25rem`. |
| `--ff-gap` | semantic | `1.25rem` | 4.2.0 | Space between columns. |
| `--ff-ease` | semantic | `cubic-bezier(0.16, 1, 0.3, 1)` | 4.2.0 | Easing for every transition. |
| `--ff-duration` | semantic | `200ms` | 4.2.0 | Duration for every transition. |
| `--ff-column-width` | component | `300px` | 4.2.0 | Width of a column. |
| `--ff-tray-bg` | component | `var(--ff-surface-sunken)` | 4.2.0 | Column tray background. |
| `--ff-tray-radius` | component | `calc(var(--ff-radius) + 0.25rem)` | 4.2.0 | Column tray corner radius. |
| `--ff-card-bg` | component | `var(--ff-surface-raised)` | 4.2.0 | Card background. |
| `--ff-card-ring` | component | `var(--ff-border)` | 4.2.0 | Card ring color. |
| `--ff-card-radius` | component | `var(--ff-radius)` | 4.2.0 | Card corner radius. |
| `--ff-card-shadow` | component | `0 1px 2px 0 rgb(0 0 0 / 0.05)` | 4.2.0 | Card shadow list. It also replaces the larger shadow a card takes on hover. |
| `--ff-card-padding` | component | `0.75rem` | 4.2.0 | Space inside a card. |
| `--ff-drag-tilt` | component | `2.5deg` | 4.2.0 | Rotation of the card while it is dragged. |
| `--ff-drag-shadow` | component | `0 10px 15px -3px rgb(0 0 0 / 0.1), 0 4px 6px -4px rgb(0 0 0 / 0.1)` | 4.2.0 | Shadow list of the dragged card. |
| `--ff-placeholder-border` | component | `var(--ff-accent)` | 4.2.0 | Border of the drop gap. |

Flowforge also reads the Filament palette: `--gray-*`, `--primary-*`, `--danger-*` and `--warning-*`. It never sets them.

Notes that apply to several variables:

- The shadow variables take a shadow list. Use `0 0 #0000` for no shadow, never `none`. Flowforge combines the value with a ring, and `none` makes the whole declaration invalid.
- `--ff-surface` paints the sticky lane-header strip behind the column headers. Set it to the background your page uses, so cards scroll under the strip without showing through.
- `--ff-card-shadow` sets the resting shadow and the hover shadow together.
- The dragged card is a clone on `body`. Flowforge copies the variables above from the card you picked up, so a value set at any scope reaches the clone.

## Hooks

Hooks are class names. Modern markup carries `ff-*` hooks only. The `flowforge-*` classes of classic boards never appear in Modern views, so a rule written for one board does not reach the other.

| Hook | Element |
|---|---|
| `ff-board` | The board root |
| `ff-column` | One column: its header and its tray |
| `ff-column-header` | The row with the title, count, summary and actions |
| `ff-count` | The card count in a column header |
| `ff-summary` | The column summary text |
| `ff-tray` | The surface that holds a column's cards |
| `ff-card` | One card |
| `ff-card-actions` | The action menu in a card's corner |
| `ff-add-row` | The add-card row, and the "Show more cards" button in a lane cell |
| `ff-lanes` | The root of the lane view |
| `ff-lane-header` | The header of one lane |
| `ff-cell` | One lane and column intersection, a drop target |
| `ff-limit-hint` | The hint shown over a full column during a drag |
| `ff-card-tag` | One tag from `CardTag` |
| `ff-card-meta` | The row of entries from `CardMeta` |
| `ff-card-avatar` | One avatar from `CardAvatar` |

Other `ff-*` classes exist for layout. They are internal.

## States

Flowforge reports state through data attributes. SortableJS toggles classes only, so `flowforge-modern.js` mirrors its states into these attributes.

| Attribute | On | Meaning |
|---|---|---|
| `data-dragging` | The dragged card clone | A drag is in progress |
| `data-placeholder` | The drop gap | Where the card will land |
| `data-drop="active"` or `data-drop="blocked"` | A column, or a lane cell | The hovered target accepts or refuses the card |
| `data-full` | A column | The column is at its limit |
| `data-collapsed` | A column | The column shows as a collapsed rail |
| `data-pending` | A card | Its move is saving |

The dragged clone sits on `body`, outside `.ff-board`. A rule that must reach it starts at `.ff-card[data-dragging]`, and the visible card is its `.ff-card-body` child.

## Customizing

Set variables in your theme and add hook rules beside them:

```css
:root { --ff-accent: var(--primary-600); --ff-radius: .5rem; --ff-drag-tilt: 1.5deg; }
.dark { --ff-card-bg: var(--gray-900); }
.ff-column[data-drop="blocked"] .ff-tray { outline: 2px dashed var(--ff-danger); }
```

The first line sets three variables for every board. The second sets a dark mode value. The third is a hook rule: it outlines a column that refuses the card you are dragging.

A variable set on `.ff-board` applies to that board only. A variable set on one card applies to that card only.

### Tailwind apps

Tailwind v4 apps can map variables to utilities with `@theme inline`:

```css
@theme inline {
    --color-ff-surface: var(--ff-surface);
    --color-ff-accent: var(--ff-accent);
}
```

`inline` keeps each utility pointing at `var(--ff-surface)`, so your overrides still apply.

### Card components

`CardTitle`, `CardTag`, `CardMeta` and `CardAvatar` are styled on Modern boards only. On a classic board they render markup with `ff-card-*` classes and no stylesheet. See [Card Components](/essentials/customization#card-components).

## Properties set with !important

Flowforge sets these properties with `!important`, to beat Filament component styles that outrank its sublayer. To override one, write your own rule with `!important` too.

| Selector | Properties |
|---|---|
| `.ff-card-meta .fi-badge` | `padding`, `font-weight`, `color`, `background`, `box-shadow` |
| `.ff-card-meta .fi-in-text-item` | `font-size`, `color` |
| `.ff-filters` | `overflow`, `background-color`, `box-shadow` |
| `.ff-filters-toolbar` | `padding-inline` |
| `.ff-filters-panel--above` | `border-bottom-width` |
| `.ff-filters-panel--before`, `.ff-filters-panel--after` | `background-color`, `border-radius`, `box-shadow` |
| `.ff-filters-indicators` | `padding-inline` |

The `.ff-filters*` classes are internal. They are listed because they carry `!important`, and they can change in any release.

## Versioning

- Adding a variable, hook or state is a minor release.
- Renaming or removing one happens in a major release only. The old name keeps working for that major through a fallback, `var(--ff-new, var(--ff-old))`, and this page marks it deprecated.

The Since column in the variable table records the release that added each variable.
